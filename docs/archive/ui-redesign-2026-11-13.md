# myterm UI/UX 重设计提案

> 状态：提案，未实施。
> 范围：`crates/myterm` 的表现层，以及一个新增的配置层。`vt` / `vt-sys` / `pty` 不动——
> 它们与「看起来怎么样、用起来顺不顺手」无关，重设计没有理由碰解析器和进程层。
> 依据：`docs/design.md`、`crates/myterm/src/{main,palette,grid_element}.rs`、
> `docs/screenshot.png` 与 `docs/screenshot-dark.png`。

---

## 一页摘要

现有界面有一套清楚的主张：标签在侧、窗格是卡片、强调色只说「当前」、chrome 随复杂度增长。
这套主张值得保留。问题不在主张，而在三处执行与三处缺口：

- **执行**：浅色模式里卡片与外壳的亮度对比只有 1.10:1（深色 1.05:1），卡片边界实际消失了；
  「抬起」在两个模式里方向相反；窗格头和网格差 5px 没有共同左边线；窗口没有名字。
- **缺口**：没有任何设置（字体、字号、shell、回滚、键位全部写死在代码里）；没有查找；
  没有命令面板，12 个快捷键只在 README 里存在。

重设计的目标不是换一套皮肤，而是让这个窗口**有身份、有边界、有键盘路径**：

1. 标题栏承担「这是哪个终端」；
2. 卡片靠一条 hairline 立住，焦点靠描边而不是把文字压暗；
3. 状态用形状 + 颜色 + 词三重编码；
4. 每个鼠标动作都有一条键，每个命令都进得了命令面板；
5. 补上设置、查找、会话恢复这三层能力。

## 一、现状盘点

### 已经做对的（不要动）

| 决定 | 为什么保留 |
| --- | --- |
| 标签在左侧，不在顶部 | 顶部那行留给窗口本身；分屏不会把侧栏撑开，终端宽度不被 chrome 抢 |
| 窗格是卡片，间隙即分隔线 | 一个正确的结构隐喻。问题只是它现在看不见（见 D7） |
| chrome 随复杂度增长 | 单窗格不画窗格头。这是全窗口最重要的一条密度规则 |
| 分隔手柄只在指针进入时出现 | 静止时零像素，动起来才说「这里能拖」 |
| 焦点不靠加粗边框去抢注意力 | 初衷对，手段错（见 D12） |
| ANSI 色注入解析器而非只改绘制 | `curl`、`ls --color` 查询到的颜色和屏幕一致。这条很少见，别放弃 |
| 退出码留在窗格底部 | 便宜、有效、无侵入 |
| 中文混排的克制 | 界面语言是一个词，不是一句话 |

### 诊断 D1–D16

分四类。★ 表示与项目自己的原则或桌面惯例冲突，不只是口味问题。

**A. 结构（能力缺口）**

| # | 问题 | 证据 |
| --- | --- | --- |
| D1 | 没有任何设置。字体族、字号、行高、光标形状、回滚行数、默认 shell、键位全部写死 | `grid_element.rs` 里 `font_size: px(14.0)`；`theme.mono_font_size` 直接取主题；`pty_command.rs` 按 pwsh → powershell → cmd 硬编码；`handle_key` 里是 match 字面量。没有 config 文件，没有 serde |
| D2 ★ | 键盘面窄，且关标签键位不在惯例位置上 | 只有 12 个动作，全在 `Ctrl+Shift`；`Ctrl+Shift+Q` 关标签（Q 在桌面惯例里属于 Quit）；没有 `Ctrl+Tab`、没有 `Ctrl+1..9`、没有查找、没有命令面板 |
| D3 | 标签不能重排、不能重命名、不能右键；关非当前标签必须「先切过去再关」 | `sidebar_close_button` 只在当前行出现；无中键、无菜单 |
| D4 ★ | 关窗立即销毁全部进程，没有提示，没有会话恢复 | `close_window` 直接 `cx.quit()` 路径；无持久化 |
| D5 ★ | 有回滚，没有查找 | README「查找未接入」，`vt` 层已暴露搜索接口 |
| D6 | 后台窗格的响铃与命令结束没有任何窗口级信号 | 状态只有「1.2 秒内有没有写字节」，且只在侧栏内可见 |

**B. 层级与视觉**

| # | 问题 | 证据 |
| --- | --- | --- |
| D7 ★ | 浅色模式卡片边界消失 | 卡片 `#FFFFFF` / 外壳 `#F4F5F1` = **1.10:1**；深色 `#111310` / `#161915` = **1.05:1**。而 `docs/design.md` 明确说「那条描边是必须的」，`render_node` 的注释说描边是「第二遍说同一件事」——**文档和实现现在互相否定**，删掉的那一方赢了，于是「卡片浮在底上」只剩一个说法 |
| D8 ★ | 「抬起」在两种模式里方向相反 | 深色：bg `#111310` < bg_soft `#161915` < surface `#191C17`（升序，正确）。浅色：bg `#FFFFFF` **>** surface `#F7F8F4` —— 被抬起的表面比网格更暗，读起来是「凹下去」 |
| D9 | 窗格头和网格没有共用左边线 | `pane_header` `pl(11px)`，网格容器 `mx(6px)`。差 5px，正好是「看得出不对但说不出哪里」的量级 |
| D10 ★ | 窗口没有名字 | 标题栏中间是一整条空拖动区；任务栏与 Alt+Tab 里只有「myterm」，多个终端窗口无法区分 |
| D11 ★ | 状态只靠颜色 | `dot_color` 用青柠 / 危险 / 灰表达 工作中 / 已退出 / 空闲；窄条里连点都没有，只靠底色（`rail_tint`）。色觉障碍下「输出中」和「空闲」不可分 |
| D12 ★ | 非焦点窗格把文字压暗 | `theme.background.opacity(0.30 / 0.42)` 蒙在整块网格上。监视另一个窗格的构建输出时，它主动降低了那段文字的对比度 |
| D13 | 强调色超预算，且明暗两套「品牌色」不是同一个深度的信号 | 常驻青柠的地方：应用标记、当前标签描边、焦点状态点、可拖间隙、更新徽章；`brand` 深色 `#C3EC74`（L≈69%）/ 浅色 `#4F7D14`（L≈28%） |
| D14 | 10px 外沿只在右和下，最大化时读作「没画完」 | `pr(px(10)) .pb(px(10))`，leading/top 为 0 |

**C. 可读性**

| # | 问题 | 证据 |
| --- | --- | --- |
| D15 ★ | 10–10.5px 的中文标签对比度不足 | 状态字用 `muted_foreground.opacity(0.8)`：浅色实测 **3.70:1**；`text_3` 本身浅色只有 2.96:1 |
| D16 ★ | 侧栏没有键盘路径；图标按钮基本没有 tooltip | 列表行只有 `on_click`，无 focus handle；除「关于」外所有 icon button 无 tooltip，窄条上的字母块尤其需要 |

### 取舍，不是错误

- 关闭控件只给当前标签（D3 的一半）：一列叉确实会变成一排按钮。**提案保留这条，另加中键与右键作为旁路**。
- 不用 Mica：后端不透明，这是硬限制，不要假装可以。
- 单窗格不画窗格头：正确，保留。
- 浅色模式用纯白网格：终端用户的口味，保留；改的是外壳和描边，不是网格。

## 二、重设计定位

一句话：**把终端当成一张一直在那儿的工作台——标签在左，格子在上，命令在键盘里。**

在原有三条之上，加三条：

| # | 原则 | 它约束什么 |
| --- | --- | --- |
| P1 | **窗口要有名字** | 标题栏中央是「哪个标签 + 在哪个目录」，不是空的拖动区 |
| P2 | **边界用线说，层级用明度说** | 卡片永远有一条 hairline；chrome 与卡片至少差 1.2:1 |
| P3 | **状态三重编码** | 形状、颜色、词三者至少取其二；颜色永远不是唯一线索 |
| P4 | **内容不被装饰压暗** | 焦点表达在 chrome 上，不在网格上 |
| P5 | **每个动作都有一条键** | 任何只在鼠标上的动作都是缺陷；面板是兜底，不是唯一路径 |

保留：标签在侧、窗格是卡片、chrome 随复杂度增长、强调色只说「当前」。

**强调色预算收敛到 4 处**：当前标签描边、当前窗格描边、可拖手柄、「有输出」状态点。
应用标记改为中性色（`text_2`），hover 才借用强调——它是身份，不是「当前」。

## 三、骨架

### 3.1 窗口

```
┌──────────────────────────────────────────────────────────────────────────┐
│ [▣]  pwsh · D:\Codes\GithubProjects\myterm  [2 窗格]      ◧ ◨  ⌕  ☀  ⓘ — □ ✕ │ 38
├───────────┬──────────────────────────────────────────────────────────────┤
│ 标签    + │ ┌───────────────────────────────┬──────────────────────────┐  │
│           │ │ pwsh  ~\myterm     ●1 ◧ ◨ ⤢ ✕ │ cmd  ~\src    ○2 ◧ ◨ ⤢ ✕ │ 30
│ ● pwsh    │ │                               │                          │  │
│ ◌ cmd     │ │ PS D:\…\myterm>               │ PS D:\…\src>             │  │
│           │ │                               │                          │  │
│           │ └───────────────────────────────┴──────────────────────────┘  │
└───────────┴──────────────────────────────────────────────────────────────┘
   56 或 240                          10px 外沿（最大化时归零）
```

标题栏三段：

| 段 | 内容 | 行为 |
| --- | --- | --- |
| 前 56px | 应用标记 28×28（x=14） | 点一下收起/展开侧栏。中性色，hover 转 `text`。不作为拖动区 |
| 中 | `pwsh`（13/600）+ `·` + 工作目录（mono 11，`text_3`，尾部省略）+ `2 窗格` 小胶囊（仅分屏时） | 文本不注册 hitbox，整段仍是拖动区；双击最大化（桌面惯例） |
| 后 | 分屏两键（仅单窗格）→ 命令面板 ⌕ → 主题 → 更新徽章 → 关于 → 10px 空格 → 最小/最大/关闭 | ⌕ 是面板唯一的发现入口，必须常驻 |

> **为什么把标签名放进标题栏**：任务栏、Alt+Tab、窗口缩略图都只读标题。现在这些地方一律显示「myterm」——
> 一个装了四个终端的窗口，在系统层面是四个一样的东西。目录名放它的右边，因为「哪个 shell」和「在哪个项目里」
> 是两个问题，第二个才是用户真正用来分辨窗口的。

### 3.2 侧栏（两档宽度，同一套行）

**列表档（240px，范围 200–360）**

```
┌ 标签                      + ┐   栏头 32px：11px text_3 + 24px 加号
│ ●  pwsh                     │   30px 行
│ ─────────────────────────── │
│ 2  cmd                     ✕ │   28px 组头（仅多窗格标签）：11.5/600 + 计数
│    ●  cmd 1                 │   30px 窗格行，缩进 16
│    ○  cmd 2        已退出 ✕  │
└─────────────────────────────┘
```

**窄条档（56px）**：一个标签一个 44px 胶囊，当前标签用 `brand` 描边；胶囊里一个或多个 30px 方块，
方块里是 12px 首字（重名用序号）。**每个方块必须有 tooltip**：全名 · 状态 · 目录。

行的解剖（左右两条 align spine）：

| 位置 | 尺寸 | 内容 |
| --- | --- | --- |
| 0–12 | 12px | 状态字形（6px） |
| 12–20 | 8px | 间隙 |
| 20–flex | flex | 名字 12px，`text` 或 `text_2` |
| 尾 −10 | 10px | 状态词 10.5px `text_3`（仅「输出中」「已退出」「完成 12s」） |
| 尾 −18 | 18px | 关闭，hover 才出现；任意标签都可 hover 关、中键关 |

选中：整行铺 `surface`（浅色下是白，比 chrome 亮），名字加 600。**不加左侧色条**——那会破坏圆角轮廓，
而且这一列已经靠文字对齐了。

新增：行右键菜单（重命名 / 关闭 / 关闭其他 / 左移 / 右移 / 复制标题 / 在此分屏）。

### 3.3 窗格头（只在分屏时出现，30px）

```
┌ pwsh      ~\myterm                         ○  1  ◧  ◨  ⤢  ✕ ┐
  10px                                      状态字形  22px 一个
```

- **名字与网格文字共用 10px 左边线**（修 D9）。状态字形和动作一起退到尾端，成为「元信息」而不是「主信息」。
- 状态字形：实心圆 = 有输出；空心圆 = 空闲；方块内一叉 = 已退出；`!` 字 = 上一条命令非零退出。
- 动作静止时 `opacity 0.55`，hover 到 1.0。不是完全隐藏——完全隐藏的动作对键盘用户和第一次使用的人是零。
- 焦点：`name` 用 `text` + 卡片 1px `brand` 描边；失焦：`name` 用 `text_2` + 1px `stroke` 描边。
  **删掉文字蒙雾**（修 D12）。1px 描边画在卡片已有的边带里，不产生任何像素位移——原来的承诺保住了，手法换了。

### 3.4 网格

| 参数 | 现在 | 提案 |
| --- | --- | --- |
| 内缩 | 水平 6 / 垂直 6 | 水平 10 / 垂直 6（与窗格头共用左边线） |
| 回滚条 | 右侧 3px 轨，12% 不透明度 | 右侧 6px 槽，静默时 0.35，hover 0.6；拖动时显示 `1234 / 5000` |
| 尺寸提示 | 无 | 改列数/行数时，焦点卡右下角浮出 `120 × 32`（mono 12，pill 底），900ms 后淡出 |
| 选区 | 强调色 20% / 30% | 不变 |
| 右键 | 无 | 复制（无选区则禁用）/ 粘贴 / 全选 / 清屏 / 向右分屏 / 向下分屏 / 查找 |

尺寸提示是替代「常驻状态栏」的方案：`vim` 和 `tmux` 用户需要知道行列数，但那不是一个值得永久占用 22px 的信息。
按需出现，静止时为零。

### 3.5 三个新表面

**查找（`Ctrl+Shift+F`，卡片内浮层，36px）**

```
┌ ⌕ [              ]   Aa   3/27   ▲  ▼                        ✕ ┐
```

- 覆盖在焦点卡片顶部，不遮住输出；不压暗其余部分。
- 全部命中：`brand` 12% 淡底；当前命中：`brand` 32% 底 + 1px 下划线。ANSI 背景色之上叠，透明度相乘。
- 空查询不显示任何高亮；0 命中显示 `无匹配`（`text_3`），不把输入框染红。
- `Esc` 关闭并把焦点还给网格；`F3` / `Ctrl+Shift+G` 下一处，`Shift+F3` 上一处。

**命令面板（`Ctrl+K`，560×最多 400，顶部偏移 12%）**

- 分组：标签 / 窗格 / 视图 / 应用。行 32px，右侧 mono 11 显示快捷键。模糊匹配名称与关键字（含中文）。
- 同时是「跳到标签」的快速切换器：输入标签名即可直达。
- 上下键移动、`Enter` 执行、`Esc` 关闭并把焦点还给终端。
- 这是 D2 的真正答案：快捷键不必背，面板负责发现；键位负责速度。

**设置（`Ctrl+,`，右侧 360px sheet，无遮罩）**

无遮罩是刻意的：改字号要当场看见终端变。分组：

| 组 | 项 |
| --- | --- |
| 外观 | 主题（跟随系统 / 亮 / 暗）、字体、字号 12–20（步进 1，实时）、行高 1.0–1.4、光标形状四选、闪烁开关 |
| 终端 | 默认 Shell（从 PATH 探测的列表里选）、回滚 1000–50000、响铃（视觉 / 声音 / 无）、复制去尾随空白 |
| 键位 | 只读列表 + 「在编辑器中打开 config.toml」链接；冲突项标红并说明 |
| 关于 | 版本、安装状态、检查更新、GitHub（从现有 about 卡片搬来） |

存储：`%APPDATA%\myterm\config.toml`，写入防抖 300ms。
读失败 → 全部默认值 + 标题栏一次性提示 `配置文件有误，已使用默认设置 · 查看`（点击打开文件所在目录）。

### 3.6 会话与关闭

- 退出时写快照：标签结构、分屏树与比例、每个窗格的启动命令与 cwd、侧栏宽度与档位、主题、窗口 bounds。
- 启动时**不自动恢复**，而是在标题栏下出现一条可关闭的提示带：`恢复上次的 3 个标签？` / `恢复` / `忽略`。
- 关窗时：标签或窗格数 > 1 且未勾选「不再提示」→ `还有 3 个窗格在运行`，动作为 `仍然关闭` / `取消`。
  单标签单窗格直接关。**不做「进程是否还在跑」的检测**——ConPTY 下没有可靠的判定，假装有就是骗人。

### 3.7 后台信号

| 事件 | 表面 | 文案 |
| --- | --- | --- |
| 非焦点窗格响铃（`\a`） | 标签行 8px 徽章 + 任务栏闪烁 | — |
| 非焦点窗格一条命令结束且耗时 > 5s | 侧栏行尾状态词 | `完成 12s` / `失败 · 1` |
| 进程退出 | 状态字形 + 行尾词 | `已退出` |
| 更新可下载 | 标题栏徽章（保留现状） | `更新 0.4.0` |

## 四、视觉系统

### 4.1 表面（这是本提案改动最大的地方）

**现在的方向问题**（D7 / D8）：深色模式的表面是升序（网格最暗，抬起最亮），浅色模式是降序（网格最亮，抬起更暗）。
同一套 token 在两种模式下表达相反的层级。修法不是调数值，而是先定一条规则：

> **抬起 = 比所在底更亮**，两个模式都成立。因此浅色模式的 chrome 必须比网格暗。

| token | 深色（现在） | 深色（提案） | 浅色（现在） | 浅色（提案） |
| --- | --- | --- | --- | --- |
| `bg` 网格 | `#111310` | `#101210` | `#FFFFFF` | `#FFFFFF` |
| `bg_soft` 外壳 / 标题栏 / 侧栏 | `#161915` | **`#1A1D18`** | `#F4F5F1` | **`#E7EADF`** |
| `surface` 抬起的行 / 胶囊 | `#191C17` | **`#22261E`** | `#F7F8F4` | **`#FFFFFF`** |
| `stroke` 描边 | `#2A2F27` | **`#33382D`** | `#E4E6DF` | **`#D2D6C6`** |
| `text` | `#F4F6F0` | `#F2F5EC` | `#13160F` | `#14170F` |
| `text_2` | `#A4AB9B` | `#A6ADA0` | `#5D6356` | `#555B4D` |
| `text_3` | `#6F7768` | **`#8A9281`** | `#8B9184` | **`#656B5C`** |
| `brand` | `#C3EC74` | `#C6EE7A` | `#4F7D14` | `#3F6B12` |
| `brand_wash` | `#262B23` | `#262B23` | `#EEF0EA` | `#EDF4DC` |
| `danger` / `amber` / `sky` | `#FF6B6B` / `#F5B84A` / `#7CC7FF` | 不变 | `#C02B2B` / `#9A6B00` / `#1F5FB4` | `#B12B26` / `#8A5E00` / `#1F5FB4` |

实测对比度（WCAG 公式，`python` 算的，不是估的）：

| 关系 | 现在 | 提案 |
| --- | --- | --- |
| 卡片 vs 外壳 | 浅 1.10:1 / 深 **1.05:1** | 浅 **1.22:1** / 深 **1.10:1** |
| 卡片描边 | 无 | 浅 1.48:1 / 深 1.56:1 |
| `text_3` on 外壳 | 浅 **2.96:1** / 深 3.81:1 | 浅 **4.52:1** / 深 **5.28:1** |
| 状态词（`text_2` @0.8） | 浅 **3.70:1** | 改为 `text_3` 满值 → 4.52:1 |
| `brand` on 卡片 | 浅 4.91:1 | 6.32:1 |
| `text_2` on 外壳 | 浅 5.67:1 | 5.76:1 |

> 两个模式的处理不对称，这是有意的：
> **浅色**必须把外壳压深——白卡片放在近白底上，色调差 1.10:1 是任何描边都救不回来的；
> **深色**继续靠 10px 间隙 + 1.41:1 的描边，因为再把外壳提亮到 1.2:1 会让窗口框比终端还显眼。
> 深浅的结构一致，手段可以不一样；不一致的是「抬起必须更亮」这条规则，两个模式都守住了。

> 1.22:1 仍然很轻。它配合 1px 描边才成立——**两者一起去掉任何一条，浅色模式就退回现在这张看不出卡片的截图**。

### 4.2 类型

| 用途 | 字号 / 字重 |
| --- | --- |
| 窗口标题（标签名） | 13 / 600 |
| 目录、路径、尺寸提示 | mono 11 / 400，`text_3`，尾部省略 |
| 侧栏名字 | 12 / 400（选中 600） |
| 栏头、组头 | 11 / 500，`text_3` |
| 状态词 | 10.5 / 400，`text_3`（**不再用 opacity 打折**） |
| 终端网格 | mono 14（可配置 12–20），与主题字号同一轴 |

中文不使用全大写、不加大字距。10.5px 是下限：再小就要靠提高对比度补偿，而那正是现在缺的。

### 4.3 圆角与间距

圆角四档：`4`（kbd/徽章）、`8`（行、按钮）、`10`（胶囊、chip）、`12`（卡片）。胶囊用 `999`。
间距六档：`4 / 6 / 8 / 10 / 12 / 16 / 24`。所有数字进一个 `space()` 函数，避免散落。

窗口外沿与圆角联动：

| 状态 | 外沿 | 卡片圆角 |
| --- | --- | --- |
| 窗口化 | 10px，四边一致 | 12 |
| 最大化 | 0（工作区长到屏幕边缘） | 0 |

这样 D14 的「L 形外壳」问题消失：要么四边等距（窗口化），要么彻底满幅（最大化），不再有「三边有边距、一边没有」的中间态。

## 五、键位

`Ctrl+Shift` 命名空间是必须的——`Ctrl+W` 是 readline 的删词，`Ctrl+N` 是下一条历史，`Ctrl+R` 是反查，
终端无权占用。但命名空间内部可以更讲道理：

| 动作 | 现在 | 提案 | 理由 |
| --- | --- | --- | --- |
| 新建标签 | `Ctrl+Shift+T` | 保留 | 与 Windows Terminal 一致 |
| 关闭 | `Ctrl+Shift+W` 关窗格 / `Ctrl+Shift+Q` 关标签 | `Ctrl+Shift+W` 关窗格（**最后一个窗格时关标签**），`Ctrl+Shift+Q` 让给退出应用 | 「一个窗格就是一个标签」的模型下不必有两个键；Q 回到 Quit |
| 切标签 | 无 | `Ctrl+Tab` / `Ctrl+Shift+Tab` | 最标准的桌面多标签手势 |
| 直达标签 | 无 | `Ctrl+1..9`（9 = 最后一个） | 同上 |
| 重开刚关的标签 | 无 | `Ctrl+Shift+R`（栈深 10） | T 已被新建占用，用 R |
| 分屏 | `Ctrl+Shift+D` / `E` | 保留 | — |
| 缩放窗格 | `Ctrl+Shift+Z` | 保留 | — |
| 侧栏档位 | `Ctrl+Shift+B` | 保留 | — |
| 主题 | `Ctrl+Shift+L` | 保留 | — |
| 查找 | 无 | `Ctrl+Shift+F`；`F3` / `Shift+F3` 上下条 | — |
| 命令面板 | 无 | `Ctrl+K` | VS Code 惯例 |
| 设置 | 无 | `Ctrl+,` | 平台惯例 |
| 全选网格 | 无 | `Ctrl+Shift+A` | — |
| 窗格导航 | `Alt+方向` | 保留 | 按几何而非按树，正确 |
| 字号 | 无 | `Ctrl+=` / `Ctrl+-` / `Ctrl+0` 复位 | 从「设置里改」升级为「随时改」 |

面板里每条命令都标注自己的键位——键位表不复述，它就长在动作旁边。

## 十、风险与取舍

1. **浅色 chrome 变深是一眼可见的风格变化**。收益是边界回来、`text_3` 达标；代价是「轻盈感」减少。
   如果保留浅 chrome，就必须把 hairline 加重到 1.58:1 以上，否则卡片继续消失——**两者只能选一个**。
2. **状态从「点」变「字形 + 词」会增加侧栏的墨水**。用「只在非默认态出现」这条规则压住它。
3. **命令面板是新的学习成本**，但它把 12 个隐藏键位变成了一次搜索，净收益为正。
4. **配置层引入文件**：损坏、迁移、默认值三件事必须一次做对，否则用户会得到一个打不开的终端。
   兜底：解析失败永不 panic，一律回落默认 + 一次提示。
5. **查找高亮与 ANSI 背景叠加**可能与某些配色撞在一起，需要在 16 色 × 深浅四组里各看一遍。
6. **标题栏放目录**会挤掉拖动区宽度。目录用尾部省略，且整段仍是拖动区，不会挡住移动窗口。

## 十二、验收清单

按 GPUI Kit 的设计评审顺序，逐条对着实现问：

1. 新用户能不能在不读 README 的情况下找到「分屏」和「改字号」？（面板 + 设置）
2. 每个动作的名称、状态、范围、结果是否一致？（尤其「关闭」的三种粒度：窗格 / 标签 / 窗口）
3. 拿掉强调色截图，还能不能看出「当前是哪个窗格、哪一行被选中」？（形状与明度必须独立成立）
4. 两种模式、100%/125%/150% 缩放、最小窗口 720×480 下各走一遍。
5. 每个只靠 hover 出现的控件，是否都有键或菜单路径？
6. 所有 11px 以上文字对各自底 ≥ 4.5:1；卡片与外壳 ≥ 1.2:1 且有 hairline。
7. 关窗、崩溃重开、配置文件损坏三种失败态各试一次。
