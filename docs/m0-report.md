## 2. 关键发现

### 2.1 构建：Zig 版本是个坑

- crates.io 的 `libghostty-vt 0.2.2` 固定了一个要求 **Zig 0.15.2** 的 Ghostty commit，而本机是 Zig 0.17。
- git `master`（本次锁定 `4230bfe2`）要求 **Zig 0.17.x**，构建通过。
- 结论：**用 git commit 锁定**，并在 README 写清 Zig 版本；升级 Ghostty 与 Zig 必须成对进行。
- 首次构建约 1.5 分钟、Zig 缓存 ~344 MB；离线构建用 `GHOSTTY_SOURCE_DIR` + `GHOSTTY_ZIG_SYSTEM_DIR`。

### 2.2 输入通道（原设计最大风险 R1）：结论是可行，但有三个必须做的细节

1. `input()` 的 `onChange` 报告的是**累积文本**，不是本次增量。必须自己按前缀差发送增量，否则 `ls` 会变成 `lls`、再变成整行重复。
2. `Enter` 之后必须清空该缓冲（shell 已换行），否则下一条命令的增量前缀对不上。
3. 绑定必须用 `on_key_with(.., KeyOptions { when: When::Always, repeat: true })`：默认 `When::Auto` 时，焦点在 `input` 上会让 Backspace、方向键等被输入框吃掉，终端收不到。
4. `on_key` 对保留键（如 `ctrl+q`、`alt+f4`、`f11`）会 **panic**，绑定表要先过滤，不能盲绑。

验证过的编码结果（`key::Encoder`，读终端模式）：

| 输入 | 发往 PTY |
| --- | --- |
| `Enter` | `\r` |
| 单字符 `é` | UTF-8 `c3 a9` |
| `Ctrl+C` | `03` |
| `↑` | `1b 5b 41` |

### 2.3 NSH 布局问题：底部/低处的同级视图不绘制

复现：根视图 = `[22pt 状态条][flex_1 Canvas]`。
- 状态条放在 Canvas **之前**（顶部）→ 正常绘制。
- 状态条放在 Canvas **之后**、绝对定位 `bottom(0)`、或放在 `y=500/600/650` → **完全不绘制**（位置由 `on_layout` 确认正确）。
- 绝对定位在 `y=300` 覆盖到 Canvas 上方 → 正常绘制。
- Canvas 自身内容可以画到窗口底部。

即：**Canvas 之外、落在窗口下半部的常规视图不出现**；Canvas 区域内的覆盖层正常。当前 workaround：状态条放在顶部；终端画布用 `flex_1` 占满其余空间。

影响：设计的「底部情境状态条」暂时不可用；命令面板/查找条（覆盖在 Canvas 上方、靠上位置）不受影响。需要给 NSH 做一个最小复现并反馈；在修复前，状态信息放顶部，或改用 `Overlay` 验证。

### 2.4 性能

| 网格 | vt（解析+取帧） | Canvas 录制 | NSH paint | present |
| --- | --- | --- | --- | --- |
| 135×41 | 0.34–0.39 ms | 0.16–0.23 ms | 0.25–0.3 ms | 0.1–0.2 ms |
| 200×51 | 0.35–0.91 ms | 0.16–0.42 ms | 0.25–0.5 ms | 0.1–0.2 ms |

- 设计预算（200×50 单帧 < 8 ms）余量约 10×；**暂不需要切换原生组件渲染**（设计 §4.4 的方案 B）。
- 空闲时 NSH 不产生帧（`fps 1/165`，即不重绘），进程 CPU ≈ 单核 1.6%。
- 大输出时靠「VT 线程满速解析 + 帧 16 ms 节流 + UI 只取最新帧」保持流畅；`1..20000` 期间无长任务。
- 内存 95–105 MB（含 2–5 万行回滚）；后续可加回滚行数上限配置与单元格 `String` 复用（当前每帧每格一次分配，此规模无感）。

## 3. 与设计文档的差异

| 设计 | M0 实际 | 处理 |
| --- | --- | --- |
| Zig 0.17.x | 取决于依赖源：crates.io 0.2.2 需 0.15.2，git 需 0.17 | 锁 git commit + README 说明 |
| 底部情境状态条 | NSH 下半部同级视图不绘制 | 先置顶；待 NSH 修复后按设计放底部 |
| 输入「隐藏 input + keymap」 | 可行，但需增量去重、Enter 清缓冲、`When::Always`、过滤保留键 | 已写进 `docs/design.md` §4.5 与代码 |
| 单字符走 encoder | 可行 | 保留；长文本（粘贴/IME 提交）按 UTF-8 直写 |
| 帧按脏行投递 | 暂未用 `next_dirty`，每帧整屏 | 性能足够，留作优化项 |
