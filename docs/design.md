# myterm — Windows 终端设计文档

> 状态：设计稿（v0.2，2026-05-20，含 M0 验证结论）
> M0 技术验证报告：[`m0-report.md`](m0-report.md)
> 范围：**只做设计，不含实现**。代码、构建与验证属于后续里程碑。
> 依赖：NSH（Native Shell，本仓库当前 `nsh 0.3.0`）+ [libghostty-rs](https://github.com/Uzaaft/libghostty-rs)（`libghostty-vt` 0.2.1）

---

## 1. 目标与范围

**一句话**：一个安静、精确、键盘优先的 Windows 桌面终端，外壳用 NSH 原生绘制，VT 语义交给 libghostty-vt。

### 1.1 要做

- 单窗口多标签、窗格分屏、回滚缓冲、搜索、选择与复制粘贴、链接、IME。
- 配置文件（PowerShell 7 / Windows PowerShell / cmd / WSL / Git Bash）、配色方案、字体与光标设置。
- 命令面板、情境状态栏、进程退出与启动失败的可恢复状态。
- 全部外观走 NSH 主题 token；终端 ANSI 调色板作为「数据」独立管理。

### 1.2 不做（v1 明确排除）

- 远程连接管理、SSH 客户端、文件传输面板。
- 多窗口会话共享/分离（detach）、会话恢复（v2 再谈）。
- 插件系统、脚本 API、六宫格/四宫格预设布局模板。
- macOS/Linux 移植（架构上不封死，但 v1 只做 Windows）。

### 1.3 设计原则

1. **终端内容优先**：除标签栏和极少的必要控件外，屏幕上不出现常驻装饰。
2. **键盘完整**：每个功能都有快捷键，且快捷键不与 shell 语义冲突。
3. **状态可见**：焦点在哪个窗格、是否在回滚、进程是否退出、是否无响应，都必须看得见。
4. **平台正确**：Windows 标题栏语义、DPI、ConPTY、`Ctrl+C` 语义按 Windows 用户的预期来。
5. **性能是功能**：输入到回显、大输出不卡顿，与视觉同等重要。

## 2. 任务模型

| 项 | 内容 |
| --- | --- |
| 主要任务 | 在一个持续存在的工作区里运行命令、读取输出、在多个任务间切换 |
| 核心对象 | 会话（Session）＝ 一个 shell 进程 + 一块 VT 屏幕 + 一份回滚缓冲 |
| 派生对象 | 窗格（Pane，显示一个会话）→ 标签页（Tab，一组窗格）→ 窗口 |
| 必须随时可用 | 输入、复制/粘贴、切标签、分屏、查找、新开标签 |
| 决策所需信息 | 当前目录、shell/配置文件、退出码、滚动位置、窗格焦点、搜索命中 |
| 高频动作 | 打字、`Ctrl+C`、滚回看历史、复制输出、开新标签跑另一件事 |
| 低频动作 | 改配色/字体、改键位、导入 Windows Terminal 配置文件 |

**心智模型**：终端不是「应用页面」，而是一块持续存在的工作面。因此不设侧边栏、不设导航栈、不做卡片式布局。

## 3. 平台与窗口形态

| 项 | 决定 |
| --- | --- |
| 系统 | Windows 10 1809+ / Windows 11 |
| 形态 | 单一桌面窗口，自绘标题栏（`TitleBarStyle::Hidden`）+ 系统窗口按钮区 |
| 默认尺寸 | 1100 × 700 pt；最小 640 × 400 pt（默认字号下约 76 列 × 23 行；更小则只裁剪视口，不压缩单元格） |
| DPI | 单元格尺寸按 `pixelRatio` 取整到物理像素，保证网格不糊；跨屏移动时重算列行并 `resize` PTY |
| 主题 | 跟随系统，可强制浅色/深色；配色方案独立于 UI 主题（可深色 UI + 浅色终端） |
| 窗口状态 | 记住最近尺寸、位置、最大化状态（`Storage`） |

## 4. 架构设计

### 4.1 模式选择：纯 Rust

NSH 三种模式中选 **模式 1（Rust）**，`nsh.json` 增加 `"rust": "."` 与 `"root": "App"`。

理由：

- `libghostty-vt` 是 Rust crate，且其类型是 `!Send` / `!Sync`，必须由 Rust 侧长期持有；
- Windows 上真正的 PTY 只有 **ConPTY**（`CreatePseudoConsole`），TSX 的 `process.spawn` 只能接管道，做不了终端；
- 帧级绘制（单元格网格）、按键编码、IME 组合态都需要贴住原生层；
- 本应用没有「上线后再热更界面」的需求，QuickJS 只会增加一次跨语言拷贝。

> 迁移说明：仓库当前是 TSX 模板（`nsh.json` 无 `"rust"`）。本设计落地时按 `nsh init` 的 Rust 模板重建目录结构，`App.tsx`/`App.test.tsx` 删除。未来若需要「设置页/引导页热更新」，再加 `#[native_module]` 与 TSX 入口即可，不需要改架构。

### 4.2 Crate 结构

```text
myterm/
├── nsh.json                 name/id/version/theme/rust/root
├── Cargo.toml               app crate: myterm
├── theme.json               UI 设计 token（见 §5）
├── src/
│   ├── lib.rs               #[native_module] + 根组件 App
│   ├── app.rs               窗口骨架、标签、窗格布局、键位注册
│   ├── ui/                  app 自有的 styled 组件层（Button/Tab/Menu/Field…）
│   ├── session.rs           UI 侧的会话句柄：发命令、收帧、暴露信号
│   ├── surface/             终端表面：网格绘制、命中测试、光标、选择
│   ├── settings.rs          设置读写（Storage）、配置文件、配色方案注册表
│   └── schemes.rs           内置配色方案（数据，非 token）
├── crates/
│   └── myterm-core/         纯逻辑，不依赖 NSH，可 cargo test
│       ├── pty.rs           ConPTY（portable-pty）启动/读写/resize
│       ├── vt.rs            Terminal + RenderState 线程
│       ├── frame.rs         帧数据（行/段/属性/光标/标题/退出）
│       ├── keys.rs          key::Encoder 封装
│       └── profiles.rs      配置文件发现（pwsh/cmd/wsl/git-bash）
└── tests/
```

**边界**：`myterm-core` 不知道 UI，也不碰 NSH；UI 只读帧数据和会话元信息，所有写入通过命令通道。好处是终端语义可以脱离界面跑测试（`cargo test`），UI 可以热改。

### 4.3 线程与数据流

`libghostty-vt` 不线程安全，`Terminal` 一旦创建就必须固定在同一线程；而 PTY 读是阻塞的。因此每个会话三条执行体：

```text
   ConPTY ──bytes──▶ [PTY 读线程]
                        │ mpsc（原始字节块，合并后投递）
                        ▼
              [VT 线程] Terminal + RenderState
                │  vt_write() 解析
                │  render_state.update() → Snapshot（脏行）
                │  折叠成纯数据 Frame
                ▼
          mpsc(latest-wins) ──▶ [UI 线程]
                                  signal(frame_epoch) → Canvas 重绘
   UI 按键 ──▶ myterm-core::keys（key::Encoder，读终端模式）──write──▶ PTY
```

- **VT 线程**独占 `Terminal`，因此 `!Send` 不构成问题；它同时产出 `key::Encoder`/`mouse::Encoder` 的编码结果（编码器需要读终端模式：应用光标键、kitty 键盘协议、鼠标上报模式）。
- **帧合并**：UI 只取最新帧，中间帧丢弃（`latest-wins` 槽 + `frame_epoch` 自增）。大量输出时 UI 保持 60 Hz，VT 线程满速解析。
- **脏行**：`Snapshot::dirty()` 与 `RowIteration::next_dirty()` 只投递变化的行。整帧变更（resize、切屏）用 `Dirty::Full`。
- **UI 拉取**：NSH 信号只能主线程写，用 16 ms 的 `set_interval` 排空通道并在有新帧时 `frame_epoch.update(+1)`；空闲时不产生帧、不重绘。
- **写回**：终端对查询的应答（DA1/DSR/OSC 52 等）通过 `Terminal::on_pty_write` 回调拿到，直接写回 PTY。

### 4.4 渲染方案

| 方案 | 做法 | 优点 | 风险 |
| --- | --- | --- | --- |
| **A. Canvas（采纳）** | 每窗格一个 `canvas(Painter)`，按行绘制背景矩形 + 按样式分段 `fill_text` | 与 NSH 合成、圆角/覆盖层/弹层天然正确、可移植 | 每帧重新录制绘制指令；字形回退/连字能力受平台文本引擎限制 |
| B. 原生组件 | `#[native_components(windows)]` 注册 `myterm.grid`，用 Direct2D/DirectWrite 自绘 | 最快，可做字形缓存、连字、亚像素 | Windows 专属实现，需自管文本排版；两套渲染代码 |
| C. 文本元素 | 每行一个 `Text` + 多个 span | 文字质量最好 | 单元格背景/选择/光标/宽字符无法对齐，节点数爆炸 |

**决定**：v1 用 A，并把绘制收在 `surface` 模块的 `draw_grid(frame, metrics, style)` 单点，保持可替换。切换 B 的触发条件（见 §11 性能预算）：
- 200 × 50 网格单帧绘制 > 8 ms，或
- 大输出时 `nsh run --fps` 掉到 45 fps 以下，或
- CJK/emoji 宽度、框线字符质量不可接受。

**M0 实测**（200×51，Rust debug 构建）：`vt` 0.35–0.9 ms、Canvas 录制 0.16–0.42 ms、NSH `paint` 0.25–0.5 ms、`present` 0.1–0.2 ms；距 8 ms 预算约 10× 余量，**暂不切换 B 方案**。

**绘制顺序**（每帧）：背景色 → 逐行背景块（合并同色相邻单元格）→ 逐行文本段（按前景色/属性分段）→ 下划线/删除线 → 选择高亮 → 搜索命中 → 光标 → 图形（phase 2）。

**单元格度量**：`measureText("M")` 得到列宽并向下取整，行高 = `round(font_size × line_height)`；宽字符占 2 列，尾部单元格跳过。网格内边距 `padding = 8`（可配置），列行 = `floor((w - 2p) / cell_w)`、`floor((h - 2p) / cell_h)`。

### 4.5 输入通道

NSH 没有给任意视图发原始按键事件的 API（只有全局 `keymap` 与 `input` 的文本事件）。设计采用三路合并，**这是全案最大的技术风险，必须在 M0 验证**：

1. **可打印文本 / IME**：每个窗格叠一个 1 pt 透明 `input()`（`caret(false)`、`autoFocus`、`paste_behavior(Report)`）。普通字符走 `on_key_press`（每次一个字符，不再依赖累积文本），组合键走 `on_key`；IME 提交的文本经 `on_composition_change` 的 composing 状态 + `on_change` 发送；`onCompositionChange` 的组合串可作为「预编辑文本」画在光标处。
2. **特殊键与组合键**：`on_key_with` 按 keystroke 绑定，**必须 `when: Always`**（默认 `Auto` 会让 Backspace/方向键被聚焦的 input 吃掉）；`escape`、`tab`、`enter`、`backspace`、`delete`、`insert`、四个方向、`home`/`end`、`pageup`/`pagedown`、`f1`–`f24`、`ctrl+a`–`ctrl+z`、`alt+*`、`ctrl+shift+*`。由 `key::Encoder` 依据终端模式（应用光标键、kitty 协议）生成字节。绑定表必须过滤平台保留键（`ctrl+q`、`alt+f4`、`f11` 等），否则 `on_key` 会 panic。
3. **应用快捷键**：先于终端键匹配（`Ctrl+Shift+T` 等，见 §7.1）；不匹配才进入 2 / 1。

**焦点**：窗格焦点 = 该窗格的 input 获得键盘焦点。点击窗格时 `input.focus()`；焦点窗格画 1 pt `focus-ring` 内描边，非焦点窗格无描边且光标以 50% 不透明度显示（失焦光标仍可见，但弱化）。

**回退方案**（若后续发现某类键无法覆盖，例如 AltGr、部分 IME 行为）：把终端表面换成 B 方案的子 `HWND` 组件，由组件自己接 `WM_KEYDOWN`/`WM_CHAR`/`WM_IME_*`。代价是该区域会盖住 NSH 绘制内容（弹层需移出该区域或临时隐藏），因此只在必要时采用。

**M0 结论**：文本、Enter、Backspace、方向键、Ctrl+字母（含 `Ctrl+C` → `0x03`）均已验证；中文 IME 仅验证了回调触发，仍需人工实测。

### 4.6 滚轮与回滚

NSH 0.3 的通用视图没有滚轮事件（原生组件与 `Scroll` 有）。设计：

- **v1**：回滚用键盘（`Shift+PageUp/PageDown`、`Ctrl+Shift+Up/Down`、`Shift+Home/End`），滚动条只是 4 pt 的指示条，可拖拽。
- **v1.1**：用 `Scroll` 承载视口（内容高度 = 回滚行数 × 行高，Canvas 固定在视口上按 `onScroll` 偏移绘制可见行），或等 NSH 暴露 `onWheel`。
- **v2**：切到 B 方案时直接获得 `wheel` 回调，支持平滑滚动（`RenderState::set_overscan` 已为此设计）。

### 4.7 构建约束（必须写进 README）

- `libghostty-vt` 构建时需要 Zig 在 `PATH`（或 `ZIG`），默认在构建期拉取固定 commit 的 ghostty 源码。**版本必须与依赖源匹配**：crates.io 的 0.2.2 要求 Zig **0.15.2**，git master（本次锁 `4230bfe2`）要求 Zig **0.17.x**。M0 采用 git commit 锁定 + Zig 0.17.0。
- 离线/可复现：设置 `GHOSTTY_SOURCE_DIR` + `GHOSTTY_ZIG_SYSTEM_DIR`。
- 静态链接 `libghostty-vt.a`；Windows 目标 `x86_64-pc-windows-msvc` 受支持（M0 已验证）。首次构建约 1.5 分钟，Zig 缓存约 340 MB。
- `libghostty-vt` 仍是 pre-1.0，API 可能破坏性变更：**在 `Cargo.toml` 按 git commit 锁定，并保留升级 PR 的回归测试**（`conpty_output_reaches_the_terminal_grid` 等 VT 测试）。
- Rust 1.90+、edition 2024。

## 5. 设计系统

### 5.1 定位

终端只有三类表面：**窗口外壳**、**终端画布**、**浮层**。外壳与浮层用 NSH token；画布颜色来自配色方案（属于数据，允许写死色值，但只能在 `schemes.rs` 与 `theme.json` 两处定义）。

### 5.2 UI Token（`theme.json`）

在默认主题之上新增角色（浅色 / 深色）：

| Token | 用途 | Light | Dark |
| --- | --- | --- | --- |
| `background` | 窗口底色 | `#ffffff` | `#0f1115` |
| `foreground` | 主文字 | `#1a1c1f` | `#e6e8ec` |
| `surface` | 标题栏/标签栏底色 | `#f6f7f9` | `#15181d` |
| `surface-foreground` | 标题栏文字 | `#3c4148` | `#c3c8d1` |
| `tab-active` | 选中标签底 | `#ffffff` | `#1e232b` |

| `tab-inactive-foreground` | 未选中标签文字 | `#6b7280` | `#9aa2ae` |

既有 token（`muted`、`muted-foreground`、`border`、`popover`、`accent`、`card`）继续用于浮层与控件。

### 5.3 配色方案（数据）

`schemes.rs` 定义，每套包含 `background`、`foreground`、`cursor`、`cursor_text`、`selection_background`、`selection_foreground`、ANSI 16 色 + bright 16 色。v1 内置：

| 名称 | 定位 |
| --- | --- |
| **Graphite Dark**（默认） | 中性灰底，低饱和，长时间阅读 |
| **Paper Light** | 白底，适合打印/展示与系统浅色 |
| **High Contrast** | 纯黑底 + 纯白字 + 高对比 ANSI，供无障碍与投影 |

配色方案与 UI 主题解耦：深色 UI + 浅色终端是合法组合；切换时只重绘画布，不动外壳。

**对比度约束**：`foreground` / `background` ≥ 7:1；光标、选区、ANSI 基本 8 色对背景 ≥ 3:1（终端调色板里高亮色天然偏亮，不做 4.5:1 的硬门槛）。新增或导入方案时跑内置自检（`myterm-core` 单元测试）：低于阈值的方案仍可使用，但设置页给出「对比度偏低」提示。

### 5.4 字体与网格

| 项 | 默认 | 范围 |
| --- | --- | --- |
| 字体 | Cascadia Mono（Windows 11 自带） | 可选/自定义，回退列表见上 |
| 字号 | 13 pt | 9–32 pt |
| 行高 | 1.25（取整到物理像素） | 1.0–1.6 |
| 加粗/斜体 | 用同族的真实字重/斜体；无粗体时用合成加粗 | — |
| 连字 | **v1 关闭**（网格对齐优先）；v2 以整行文本段渲染可选开启 | — |
| 内边距 | 8 pt（可配 0–24） | — |

字号变化时：重算单元格 → 重算列行 → `Terminal::resize(cols, rows, cell_width_px, cell_height_px)` → 重排回滚（libghostty 自带 reflow）。

### 5.5 间距、圆角、密度

- 间距只用 2 / 4 / 8 / 12 / 16 / 24 的阶；终端区域不吃 UI 间距。
- 圆角：标签 6，popover/命令面板 10，按钮/输入框 6；终端画布 0（满贴）。
- 密度：Windows 桌面「紧凑」档 —— 工具栏按钮 28 pt，标签 32 pt，状态条 22 pt，菜单行 28 pt。触摸屏不设目标（Windows 平板模式沿用系统缩放）。

### 5.6 图标

单一线性图标族（NSH 内置字符/自绘 SVG），线宽 1.5 pt。图标只用于：新建标签 `+`、配置文件下拉 `⌄`、关闭 `×`、查找、分屏、更多 `⋯`。所有图标按钮必须有 `accessibilityLabel` 与 tooltip（含义或快捷键）。

```text
│                                                                             │
│  PS C:\src\myterm> █                                                        │
├────────────────────────────────────────────────────────────────────────────┤
│ 第 812 / 10,000 行 · 已选 124 字符                                          │ 22 pt 情境状态条
└────────────────────────────────────────────────────────────────────────────┘
```

- **标题栏**：自绘，40 pt，`windowDrag(true)`；左侧 8 pt 起放标签，右侧让出 `title_bar().right`（Windows  caption 按钮宽度）。双击空白处最大/还原由平台处理。
- **标签**：高 32 pt，圆角 6，内边距 8/6；宽度 110–220 pt，超出截断加省略号。内容 = 状态点（6 pt，仅有状态时出现）+ 标题（进程标题优先，否则配置文件名的会话序号）+ 关闭按钮（悬停或选中时显示，宽 16）。选中标签用 `tab-active` 底与前景；未选中用 `tab-inactive-foreground`，无底。
- **`+` 与 `⌄`**：`+` 直接按默认配置文件新开标签；`⌄` 打开配置文件菜单（见 §6.6）。二者都是 28 × 28 的图标按钮，带 tooltip 与快捷键提示。
- **标签溢出**：标签总宽超过可用宽度时，末位出现「标签列表」按钮（`⋯`），点开为菜单；不做横向滚动（Windows 上横向滚标签很难发现）。
- **无第二个标签条**：不做「标签栏 + 工具栏」双层，避免重复的导航层。

### 6.2 窗格

```text
┌──────────────────────────────┬──────────────────────────────┐
│  左窗格（有焦点，1pt 描边）   │  右窗格（无焦点）             │
│                              │                              │
│                              │                              │
└──────────────────────────────┴──────────────────────────────┘
```

- 分屏用 `ResizablePanelGroup`（v1 单层分屏，最多 4 窗格；嵌套分屏 v2）。
- 分隔线 1 pt `pane-border`，可拖拽热区 8 pt；分隔线只有一条，归父级所有，子窗格不重复画。
- 焦点窗格：1 pt `pane-border-active` 内描边（不占布局，`outline` 语义），z 序不变。
- 窗格内容：8 pt 内边距 + 画布满铺；右上角浮一个仅在悬停/搜索时出现的 28 pt 小工具组（查找、更多），不常驻。
- 窗格关闭：标签只剩一个窗格时关闭标签；关闭有前台进程的窗格需要确认（见 §6.8）。

### 6.3 情境状态条

默认隐藏。出现条件（满足任一）：有选区、正在回滚（不在底部）、查找打开、进程已退出、无响应、缩放/字体临时变化。内容示例：`已选 124 字符 · 第 812 / 10,000 行`。右侧固定显示 `列 × 行`（resize 时短暂高亮）。

> **M0 约束**：NSH 0.3 在 Windows 上不绘制 Canvas 之下 / 窗口下半部的同级视图（详见 `m0-report.md` §2.3）。在修复前，状态条置于终端画布**上方**（或等待 NSH 修复后回到设计位置）；命令面板、查找条等覆盖在画布上方、靠上的浮层不受影响。

这样避免常驻状态栏吞噬垂直空间，同时保证「看不见的状态」在需要时可见。

### 6.4 命令面板（`Ctrl+Shift+P`）

```text
        ┌ 命令面板 ──────────────────────────────────────────┐
        │  分屏                                              │
        ├────────────────────────────────────────────────────┤
        │  向右分屏                                 Ctrl+Shift+D │
        │  向下分屏                                 Ctrl+Shift+E │
        │  选择配置文件…                                     │
        │  切换配色方案…                                     │
        │  打开设置                                       Ctrl+,  │
        └────────────────────────────────────────────────────┘
```

- 位置：窗口水平居中，顶部 96 pt；宽 560 pt（窄窗口取 `min(560, 宽度-32)`），高 360 pt，结果列表虚拟化。
- 输入即过滤；`Enter` 执行选中项，`↑/↓` 移动，`Esc` 关闭；无结果时显示「没有匹配的命令」+ 建议。
- 命令来源 = 应用命令 + 配置文件 + 配色方案；每条命令显示快捷键（`key_label`），保证与真实绑定一致。

### 6.5 查找（`Ctrl+Shift+F`）

```text
                                        ┌ 查找 ──────────────────────────┐
                                        │ cargo   Aa  .*   3/12   ↑  ↓  × │
                                        └────────────────────────────────┘
```

- 停靠在焦点窗格右上角，浮在内容之上；宽 360 pt，高 36 pt。
- 字段：查询框、区分大小写、正则、命中计数 `当前/总数`、上一处/下一处、关闭。
- 命中全部高亮（`search-match`），当前项更强（`search-match-current`）；`Enter`/`Shift+Enter` 循环；关闭后恢复滚动位置与选区。
- 无命中：计数显示 `0/0`，查询框边框用 `destructive`，不弹窗。

### 6.6 配置文件菜单（`⌄`）

菜单项：`Windows PowerShell`、`PowerShell 7`、`命令提示符`、`Ubuntu (WSL)`、`Git Bash`、分隔线、`选择配置文件…`（打开设置）、`以管理员身份新建标签…`（触发 UAC，失败给出原因）。

每项左列图标/空格，右列显示快捷键（`Ctrl+Shift+1`…）。

### 6.7 设置（`Ctrl+,`）

独立视图（占满窗口，非弹窗——设置项多、需要探索）。

```text
┌ 设置 ─────────────────────────────────────────────────────────────┐
│  外观        │  配色方案   [Graphite Dark        ▾]                │
│  配置文件    │  跟随系统外观  [ 开 ]                               │
│  键位        │  字体        [Cascadia Mono      ▾]   字号 13       │
│  终端        │  行高        [1.25]      内边距 [8]                 │
│  关于        │  光标        ( ) 块   (•) 竖线   ( ) 下划线          │
│              │  光标闪烁    [ 开 ]                                 │
│              │  终端预览    ▏PS C:\> echo hello▕                  │
└────────────────────────────────────────────────────────────────────┘
```

- 左列导航 180 pt，右侧内容 `Scroll`，单列最大宽 640 pt。
- 每个设置项：标签 + 控件 + （必要时）一行 `muted-foreground` 说明；改动立即生效并自动保存，无「保存」按钮。
- 终端类设置旁边给一个实时预览块（用当前配色/字体渲染 3 行示例）。
- 「配置文件」页管理可执行文件路径、启动参数、起始目录、默认配置文件；路径无效时就地显示错误与「浏览…」。
- 「键位」页列出所有命令与绑定，支持录制新快捷键并检测冲突。

### 6.8 进程退出与失败

**退出（正常或非 0）**：窗格底部出现一条 32 pt 的横幅，不遮挡输出：

```text
⏹ 进程已退出，代码 1                    [重新启动  Enter]  [关闭窗格]
```

- 退出码 0 用 `success` 图标，非 0 用 `warning`；文案必须写清代码。
- `Enter` 重新启动；`Esc` 关闭窗格；横幅不抢焦点，光标停在上次位置。
- 前台有进程时关闭窗格/标签/窗口 → `AlertDialog`：标题 `关闭正在运行的 “cargo test”？`，正文只写后果，按钮 `取消` / `强制关闭`（destructive）。

**启动失败**：窗格内显示就地错误面板（不是弹窗）：

```text
无法启动 PowerShell 7
找不到 pwsh.exe。请安装 PowerShell 7，或在设置里指定路径。

[选择配置文件…]   [复制详情]   [重试]
```

- 技术细节折叠在「复制详情」里（完整命令行 + 错误码），界面只给可行动的句子。

### 6.9 右键菜单

`复制`（有选区时可用）、`粘贴`、`全选`、分隔线、`查找…`、`清空缓冲区`、分隔线、`向右分屏`、`向下分屏`、`关闭窗格`。

设置项可把右键改为「直接粘贴」（Windows Terminal 用户习惯），但菜单始终可从 `Shift+右键` 打开——不能把唯一入口藏进设置。

### 6.10 空/无标签状态

最后一个标签关闭时：窗口保留，显示居中空状态——标题 `没有打开的会话`，说明一句，主按钮 `新建 PowerShell 7 标签`，次要 `选择配置文件…`。

### 7.1 键位

原则：**`Ctrl+C` 永远发给 shell**（复制必须带 `Shift`），这是终端用户的肌肉记忆；所有应用命令都不占用 shell 常用序列。

| 命令 | 快捷键 | 备注 |
| --- | --- | --- |
| 新建标签 | `Ctrl+Shift+T` | 默认配置文件 |
| 按配置文件新建 | `Ctrl+Shift+1`…`9` | 对应菜单顺序 |
| 新建窗口 | `Ctrl+Shift+N` | v2 |
| 关闭窗格 | `Ctrl+Shift+W` | 最后一个窗格 → 关标签 |
| 下一个 / 上一个标签 | `Ctrl+Tab` / `Ctrl+Shift+Tab` | 循环 |
| 跳到标签 1–9 | `Ctrl+1`…`9` | 与 Windows Terminal 一致 |
| 向右 / 向下分屏 | `Ctrl+Shift+D` / `Ctrl+Shift+E` | |
| 在窗格间移动焦点 | `Alt+方向键` | 空间方向，非顺序 |
| 调整窗格大小 | `Alt+Shift+方向键` | 每次 2 列/1 行 |
| 缩放窗格（最大化） | `Ctrl+Shift+Z` | 再按还原 |
| 关闭分屏 | `Ctrl+Shift+W` | 焦点窗格 |
| 复制 / 粘贴 | `Ctrl+Shift+C` / `Ctrl+Shift+V` | 粘贴多行时提示确认（见 §7.3） |
| 全选 | `Ctrl+Shift+U` | `Ctrl+Shift+A` 被输入框编辑动作占用 |
| 查找 | `Ctrl+Shift+F` | |
| 命令面板 | `Ctrl+Shift+P` | |
| 设置 | `Ctrl+,` | |
| 放大 / 缩小 / 重置字号 | `Ctrl+=` / `Ctrl+-` / `Ctrl+0` | 每档 1 pt |
| 向上 / 向下翻页回滚 | `Shift+PageUp` / `Shift+PageDown` | |
| 回滚到顶 / 底 | `Shift+Home` / `Shift+End` | |
| 上 / 下滚一行 | `Ctrl+Shift+Up` / `Ctrl+Shift+Down` | |
| 清空回滚缓冲 | `Ctrl+Shift+K` | 不动当前屏幕 |
| 重命名标签 | `F2` | 就地编辑 |
| 打开链接 | `Ctrl+单击` | 悬停时链接加下划线并显示目标 |

`text` 里的按键提示统一用 `key_label()` 生成，随平台写法变化。

### 7.2 鼠标

| 操作 | 行为 |
| --- | --- |
| 单击窗格 | 聚焦该窗格 |
| 拖选 | 字符级选择，自动滚动 |
| 双击 | 选词（按 shell 的 word 边界） |
| 三击 | 选整行（逻辑行，含换行拼接） |
| 块选择 | `Alt+拖拽`（矩形选区） |
| 滚轮 | 回滚（应用不上报鼠标时）；应用上报时转发给应用（`mouse::Encoder`） |
| 右键 | 上下文菜单（或按设置直接粘贴） |
| 中键 | 粘贴（可关） |
| 拖放文件 | 插入带引号的路径；拖到标签上则在该标签打开 |
| 悬停链接 | 2 pt 下划线 + tooltip 显示 URL，`Ctrl+单击` 打开 |

粘贴多行（>3 行或以换行结尾）：先显示确认条 `粘贴 42 行？` → `粘贴` / `取消`。这是防止误执行的危险操作保护。

### 7.3 选择与复制

- 选区颜色来自 `selection` token；失焦时降低不透明度到 60%，仍可见。
- 复制时把逻辑行拼成文本（去掉自动换行、保留显式换行），并去掉行尾填充空格。
- 「复制为 HTML」/「复制为 RTF」不做（v1）。
- 关闭「选中即复制」默认关闭；开启后在设置里提示会覆盖剪贴板。

### 7.4 IME

- 组合串在光标处以「预编辑」样式绘制（下划线 + 与正文同色），组合取消时立即清除。
- 组合期间不向 PTY 发送任何字节；提交时一次性发送 UTF-8。
- 候选窗由系统绘制（走 `input()` 的原生 IME），位置跟随光标：`input` 元素需保持在光标单元格附近（每帧更新其绝对位置与 1×1 尺寸）。

### 7.5 焦点与遍历

- 焦点顺序：命令面板 > 查找 > 设置导航 > 设置内容 > 标签栏 > 窗格；`Tab` 在设置页内正常遍历，在终端内**永远发给 shell**。
- `Esc`：关闭最上层浮层；无浮层时发送给 shell。
- 弹层关闭后焦点回到触发它的控件或原窗格。

## 8. 状态矩阵

| 状态 | 触发 | 界面表现 | 恢复方式 |
| --- | --- | --- | --- |
| 启动中 | 新标签/新窗格 | 标签状态点为 `muted` 呼吸点；窗格内显示配置文件名的 1 行占位（不转圈） | 首帧到达后消失 |
| 正常 | — | 光标闪烁（可关） | — |
| 只读回滚 | 视口不在底部 | 状态条出现 + 底部浮出 `↓ 回到最新` 小按钮 | 滚到底 / 快捷键 |

| 进程退出 | 子进程结束 | 底部横幅（退出码） | `Enter` 重启 / 关闭 |

## 9. 无障碍与本地化

**无障碍**

- 终端画布作为整体暴露 `role="text"`（或 `document`）+ `accessibilityLabel`：当前行文本 + 选区摘要；`announce()` 播报 bell、标题变化、进程退出。
- 提供「屏幕阅读器模式」开关：开启后在画布下方维护一份可视区文本的隐藏镜像（`Text`，`selectable`），按行更新，供读屏连续读取；关闭时零开销。
- 焦点环始终可见（1 pt `ring`，不裁剪），所有命令可通过命令面板到达。
- 颜色不作为唯一信息载体：退出码、未响应、bell 都有文字/图标。
- 尊重减少动态效果：关闭光标闪烁与所有过渡；尊重系统文字缩放（终端字号单独设置，不与 UI 字号耦合）。
- 高对比配色方案 + 全部配色方案 ≥ 4.5:1 自检。

**本地化**

- UI 文案 zh-CN / en-US 两套；终端内容不翻译。
- 术语表（保持一致）：

| 概念 | 中文 | English |
| --- | --- | --- |
| Tab | 标签 | Tab |
| Pane | 窗格 | Pane |
| Profile | 配置文件 | Profile |
| Color scheme | 配色方案 | Color scheme |
| Scrollback | 回滚缓冲 | Scrollback |
| Session | 会话 | Session |
| Bell | 提示音 | Bell |

- 按钮文案用动词短句：`关闭窗格`、`重新启动`、`粘贴`、`取消`；短标签不带句号。
- 快捷键显示用 `key_label()`，不手写 `Ctrl` / `⌘`。
- 文案避免「管理/模块/功能」类包装词；标题不重复上下文（设置页内不再叫「外观设置」）。

## 10. 动效

- 标签切换：无位移动画，仅 120 ms 底色/前景过渡。
- 命令面板/查找条：120 ms 透明度 + 4 pt 位移；关闭 90 ms。
- 状态条出现/消失：100 ms 高度或透明度（不推动终端网格，避免 resize 抖动）。
- 光标闪烁：530 ms 方波（Windows 习惯），减少动态效果时关闭。
- 平滑滚动：v2，仅在开启且非减少动态效果时。
- 禁止：标签拖动时的弹性回弹、光标淡入淡出、输出逐字动画。

## 11. 性能预算与验证

| 指标 | 目标 | 测量方式 |
| --- | --- | --- |
| 按键到 PTY 写入 | p95 < 4 ms | `myterm-core` 基准 |
