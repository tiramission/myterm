# myterm 设计

一个 Windows 终端。目标是把「终端」这件事做对：VT 解析交给成熟的库，界面用现代的 Rust 框架，其余全部是自己的代码，且每一层都能单独测试。

## 为什么这样分层

终端应用有三个几乎无关的问题：

1. **字节到网格**。ANSI 序列、宽字符、回滚、选区、按键编码——这是 VT 解析器的工作，细节多且容易出错。
2. **网格到像素**。每个单元格的位置、颜色、装饰线、光标形状。
3. **应用外壳**。标签、分屏、快捷键、配置。

把三者混在一起，任何一处改动都会牵连另外两处。所以分成四个 crate，依赖严格向下：

```
app ──► pty
 │       ▲
 └────► vt ──► vt-sys
```

`vt-sys` 是唯一出现 `unsafe extern "C"` 的地方；`vt` 把指针所有权、错误码、颜色类型全部包装成值；`pty` 只负责进程和管道；`app` 只做界面。这条边界让「解析器崩了」和「界面画错了」永远不会混在同一个栈里。

## VT 层

### 为什么用官方 C API

之前用第三方 Rust 封装，它锁在一个 pre-1.0 的 commit 上，封装本身有近两万行。官方 1.0.0 提供了稳定 ABI 和版本承诺，代价是要自己写绑定。

绑定是手写的：本机没有 `libclang`，`bindgen` 不可用。手写反而更可控——只声明真正用到的约 40 个函数，每个常量都对着头文件核对过。

### 静态库

`libghostty-vt` 用 Zig 构建，官方不发 Windows 包。做法是在 1.0.0 源码上跑：

```sh
zig build -Demit-lib-vt -Doptimize=ReleaseFast
```

把 `zig-out/lib/ghostty-vt-static.lib`（12.5 MB）提交进仓库。这样构建机不需要 Zig、不需要网络、不需要 CMake。`build.rs` 只做两件事：检查文件在不在，然后告诉 cargo 链接它。

### sized struct

C API 里所有输出结构体第一个字段是 `size_t size`，库用它判断调用方编译时的结构体版本。Rust 侧不能靠 `derive(Default)`——那会把 `size` 置零，库会拒绝写入。每个这样的结构体都手写 `Default`，显式填 `size_of::<Self>()`。

这个坑在写测试时立刻暴露了：光标位置读出来永远是 0，因为 `GhosttyRenderStateCursor::default()` 的 `size` 是 0。

### 渲染状态

`RenderState` 是终端的一个快照。用法是固定的三段：

```rust
state.update(term.raw())?;          // 从终端刷新
state.for_each_row(|row| { ... });  // 在回调里读单元格
```

单元格数据只在 `update` 之后、下一次 `update` 之前有效。所以 `for_each_row` 的设计是「回调里读完，不要存指针」——回调收到的 `Row` 是已经拷贝出来的值，天然不可能持有悬垂引用。

### 按键编码

不自己拼 `\x1b[A`。把按键、修饰键、字符交给 `ghostty_key_encoder_encode`，它会读终端当前模式（application cursor keys、modifyOtherKeys、kitty 键盘协议），输出正确的序列。这样终端跑 `vim` 或 `htop` 时方向键不会错。

## PTY 层

ConPTY 的读和写各一个线程，中间用 channel。界面线程只做 `try_recv`，永远不会阻塞在管道上。

写也一样：`write` 把字节丢进 channel 就返回。终端程序输出快时，界面不会被写操作拖住。

## 界面层

### 绘制

终端网格不是布局问题：每格一样大，不换行，原点就是元素左上角。所以整块用一个自定义 `Element` 画，三个阶段：

- `request_layout`：声明填满父容器。**不设 `min_size`**——那会把网格撑到比容器大，画到窗格外。
- `prepaint`：从实际 bounds 算出能放几列几行，写进一个 `Rc<Cell<(u16,u16)>>` 给外壳。这是唯一知道真实尺寸的地方。
- `paint`：三遍。先画所有单元格背景（否则相邻格的字会压在后面的背景上），再画字形，最后画下划线、删除线、光标、滚动条。

光标用 `paint_quad` 画实心块、竖线或下划线，按终端报告的 `CursorStyle` 分支。

### 尺寸反馈

窗格尺寸有个循环依赖：PTY 要知道几列几行，而这个数只能从渲染后的 bounds 得到。

解法是让 `prepaint` 把实测的格数写进 `Cell`，`render` 下一帧读它并调用 `resize`。用 `Cell` 而不是 `Signal`，因为 `prepaint` 发生在渲染中，此时触发响应式更新会 panic。

### 分屏

布局是一棵树：

```rust
enum Layout {
    Leaf(u64),
    Split { axis: Axis, ratio: f32, first: Box<Layout>, second: Box<Layout> },
}
```

`Leaf` 存窗格 id，窗格本体在 `BTreeMap<u64, Pane>` 里——用 map 而不是 vec，删除一个窗格不会让其他窗格的 id 失效。

渲染时递归展开：`Split` 变成一个 `flex_row` 或 `flex_col` 容器，两个子节点各占 `flex_basis(ratio)`。让 flex 引擎分配空间，而不是自己算像素宽度，这样嵌套分屏也能正确分摊。

导航（`Alt+方向`）按几何位置算：在所有窗格矩形里找与当前窗格在同一行/列、且位于指定方向、距离最近的。按几何而不是按树，因为树的结构和用户看到的方位不一定一致。

### 焦点

终端是窗口里唯一可聚焦的东西。每次 `render` 检查焦点，被抢走就抢回来——点标签、点分屏按钮之后，键盘必须继续进终端。

窗格之间的焦点靠「变淡」而不是描边：没有键盘的卡片蒙一层与底色同色的薄雾。这样切换焦点时没有任何像素位移，也不会在已经很密的终端界面上再加一圈线。

### 定时轮询

PTY 没有事件通知，所以用一个 16ms 的定时器轮询。轮询只在有变化时 `notify`，空闲时进程是安静的。

## 布局

界面只有两层东西：**外壳**和**卡片**。

外壳是标题栏和卡片之间的空隙，用 `bg_soft`；卡片是终端本身，用 `bg`。分成多个窗格时，每个窗格是一张卡片，卡片之间留 10px 的外壳色，角落是 12px 圆角。所以窗格之间的间隔是「留出来的」而不是「画上去的线」——终端自己会铺满背景，一条 1px 的线夹在两块同色区域之间根本看不见。

窗格多于一个时，每张卡片顶部多一行 32px 的窗格头：一个状态点、一个名字，右边是悬停才出现的分屏 / 缩放 / 关闭。单窗格时不显示——上面的标签已经说了它是谁，再写一遍等于用 32px 什么也没说。这条规矩决定了整个界面的密度：**chrome 随复杂度增长**。

焦点不画边框。没有键盘的窗格整体变淡：卡片抬起一点、文字上面蒙一层与底色同色的薄雾。相比一圈描边，它更安静，而且不会在切换时移动任何一个像素。强调色只留给标题栏的应用标记、窗格头上的状态点，和悬停中的可拖动间隙。

缩放是临时的：`zoomed` 只影响渲染，布局树不动，所以放开缩放时每个窗格回到原来的位置和比例。

## 配色

ANSI 16 色和默认前景/背景通过 `ghostty_terminal_set` 注入解析器，而不是只在绘制时替换。这样跑 `curl` 或 `ls --color` 时，程序查询颜色得到的值和屏幕上的值一致。

界面用一套自己的 token（`crates/app/src/palette.rs`）：四个表面（`bg` / `bg_soft` / `surface` / `pill`）、三档文字（`text` / `text_2` / `text_3`）、一条描边（`stroke`），加一个青柠色强调（`brand`）。两层含义：

- **表面**：网格用最深的 `bg`，外壳（标题栏、窗格之间的空隙）用 `bg_soft`，抬起来的东西（选中的标签）用 `surface`。窗格因此像放在一层浅色底上的卡片，而不是几块刚好停住的矩形。
- **强调**：`brand` 只给三处用——标题栏的应用标记、键盘所在的窗格描边、可拖动的空隙悬停。强调色用在哪里，就说明哪里是「当前」的。

这些 token 会写进组件主题（`Theme::update` 覆盖 `ThemeColor`），所以库里那些现成控件也自动落在同一套颜色上，不必逐个改。深浅两套的结构完全一样，只是值不同，所以同一个界面在两种模式下读起来是同一个界面。ANSI 16 色也按这套色系重新调过，终端里的红绿黄蓝和外壳不打架。

## 测试

- `vt/tests/api.rs`：跑真实库。喂 VT 字节，读回单元格、光标、颜色、滚动条、选区、按键编码。10 个测试覆盖了绑定的每个易错点——结构体布局错、枚举值错、`size` 没填，都会在这里失败。
- `app/src/layout.rs`：6 个测试覆盖分屏。切分不留缝、奇数尺寸不丢行、删除提升兄弟、导航按几何。

这些测试不需要窗口，也不依赖 GPU。
